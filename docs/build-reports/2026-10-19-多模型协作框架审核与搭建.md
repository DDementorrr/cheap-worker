## 结论与适用范围

用户提供的“高级模型规划、低价模型执行、高级模型复核”方向适合当前 WSL 终端环境。
初始 README 和 Python MVP 只能作为原型，尚不足以对真实代码任务作可靠验收。本次已在
`/home/ww/multi_model_codex` 完成可配置、可离线验证的单任务三角色编排框架。

本次把附带文档作为待审核材料；未直接执行其中的 sudo、全局环境修改或迁移目录建议。
没有改动 `realman_ws`、PX4 或当前 Codex 的登录/模型配置。

该框架以自填 API 调用独立运行，不能自动复用本次 IDE 会话的订阅、模型或身份。
三个角色是独立的模型上下文，默认顺序协作；本版没有并行 worker 集群或 IDE 原生子会话管理。

## 初始实现审核

| 问题 | 原实现影响 | 最终处理 |
| --- | --- | --- |
| 规划输入只有任务和仓库路径 | 高级模型无法检查真实源码 | 规划器获得受限只读文件工具、文件清单、检查目录与根指令文件 |
| 仅 `git switch -c` | 新分支仍直接改动用户当前工作目录 | 自动创建独立 Git worktree，原目录与当前分支不变 |
| 审查只取 `git diff` | 新建未跟踪文件不进入审查，已暂存变更也可能遗漏 | `diff HEAD` 加新文件 no-index diff，包含修改、删除、新增 |
| 补丁固定截断至 50000 字符 | 模型可能对未见内容作 PASS | 不截断后验收，超限直接 BLOCKED |
| `verification_commands` 没有强制执行 | 执行者声明“测试通过”可能被直接采信 | 固定名称检查目录，编排器每轮独立重跑强制检查与规划检查的并集 |
| 命令按前缀放行 | 模型仍可扩展测试工具参数 | 改为名称映射到精确 argv，模型无命令后缀入口 |
| 复核只看提交材料 | 无法补查上下文或完整日志 | 独立只读复核会话，可读源码和分页检查日志 |
| 只看 decision 字段 | 漏项验收或失败测试仍可能被接受 | JSON Schema 与本地门禁，逐条固定标准检查、拦截失败命令及未结束执行 |
| 所有角色固定 Chat Completions | 难以兼容需要 Responses 的模型 | 每角色协议独立，适配两类请求、工具调用与结果续接 |
| 无全局请求/上下文上限 | 成本、死循环与资源消耗不明确 | 请求、阶段轮数、工具调用、输出 token、上下文、超时、日志量上限 |
| 子进程继承完整环境 | 模型 API 环境变量可能进入测试进程 | 精简命令环境，模型 key 默认不传入，日志脱敏 |
| 未提供测试与故障闭环 | 无 key 时无法独立验证框架 | 本地 HTTP 兼容服务、真实 SDK/CLI、完整返工演示及自动化测试 |

保留了原 `main.py --repo --task --dry-run` 终端入口形式，以及 `SOL_*`、`DEEPSEEK_*` 环境变量名。
内部配置已升级为角色、具名检查和预算结构；旧的 `allowed_commands` 前缀配置不再适用。

## 实现与本机准备

- `main.py`：稳定入口。
- `orchestrator/config.py`：显式 env 文件加载、角色/协议/预算校验。
- `orchestrator/models.py`：OpenAI SDK 的 Chat Completions 与 Responses 适配、usage 与请求预算。
- `orchestrator/agents.py`：角色工具权限、有限工具循环、结构化输出修复。
- `orchestrator/workspace.py`：worktree 辅助、文件路径保护、完整差异、具名检查与子进程清理。
- `orchestrator/schemas.py`：固定规划和复核格式、独立本地验收门禁。
- `orchestrator/artifacts.py`：运行工件、审计记录与已知 key 脱敏。
- `orchestrator/workflow.py`：规划、执行、检查、复核、返工状态机。
- `orchestrator/cli.py`：配置检查、付费 API 探测、任务启动。
- `prompts/`：三个角色提示词，明确区分用户目标与仓库/文档等不可信材料。
- `run.sh`、`scripts/setup.sh`：隔离已 source 的 ROS Python 环境，固定依赖安装。
- `.env.example`、`.env`：自填端点模板；`.env` 已建立，权限 `0600`，仍为占位值。
- `README.md`：协议选择、项目检查、真实任务、预算、工件与限制的完整说明。

本机为 Python 3.10.12、Git 2.34.1。依赖安装于本目录 `.venv`。
首次下载发生 PyPI 读超时，增加单次下载超时后成功；无需更换凭据或修改系统代理。
发现终端 ROS `PYTHONPATH` 会影响 pip 的环境视图，启动/安装脚本已对框架进程清除此变量。
清除注入后，`pip check` 返回 `No broken requirements found`。

API 实现核对了 official OpenAI documentation 的
[Function calling](https://developers.openai.com/api/docs/guides/function-calling) 和
[Text generation](https://developers.openai.com/api/docs/guides/text)。
模型 ID 和第三方兼容性以用户实际供应商为准，没有替用户选择或调用任何付费模型。

## 尚未验证与使用顺序

没有真实 API key，因此没有验证实际供应商的认证、模型 ID、计费、速率限制、工具格式或实际模型任务质量。
没有启动 ROS/PX4、机器人、相机或真机操作，也没有将某个真实业务仓库的端到端任务宣告通过。

用户接下来需要：

1. 填写 `.env`，按供应商选择 `config.yaml` 中每个角色的协议与长度参数。
2. 运行 `bash run.sh --doctor`，再用 `bash run.sh --doctor --probe` 检查真实工具往返（后者会计费）。
3. 为目标项目配置可独立运行的具名构建/测试检查。
4. 在干净的专用测试仓库先运行 `--dry-run`，再执行完整任务并检查工件。
5. 查看真实模型的质量和成本后，再用于重要项目。

worktree 是 Git 工作目录隔离，不是 OS 沙箱。具名测试/构建仍运行本机项目代码；不可信仓库需要独立容器/虚拟机。
本版仅有请求/token/时间/日志上限，没有美元级预算封顶、并行 worker、自动恢复或跨仓库工作流。
PASS 的代码保留为未提交改动，不会自动提交、合并、推送或部署。
