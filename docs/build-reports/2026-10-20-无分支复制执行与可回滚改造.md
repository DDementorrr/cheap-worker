# 无分支复制执行与可回滚改造

日期：2026-10-20。

## 改动

- 默认 `execution.mode: copy`：将目标 Git 工作区复制到运行目录，保留非敏感的已提交和未提交文件；复制品内部创建临时基线提交，仅用于产生候选补丁。
- 执行器不会切换或创建源仓库分支。`execution.mode: branch` 保留为严格模式，使用 detached worktree，仍不创建命名分支。
- 源仓库在 `execute` 前只要求存在 Git HEAD，不再要求干净。应用前比对源仓库 HEAD 和完整工作区状态，执行期间有任何变化即停止自动应用。
- 增加 `push` 命令和 `execute --push-before`。两者都要求当前分支、upstream 和干净工作区，执行普通 `git push`，不使用 force。默认不自动 push，因为这是外部仓库写操作。
- 增加 `rollback`：`APPLIED` 后记录源仓库状态，只有源仓库仍精确等于应用后的状态时，才运行 `git apply --reverse --check` 并恢复。应用后有新修改时拒绝自动恢复。
- 更新技能、调用约定、README 和离线流程说明，明确复制模式、push 边界和恢复条件。

## 复核可行性

不使用源分支仍然可以保持较高复核可靠性：执行器只在复制品工作；聊天模型复核候选补丁、实际检查日志和快照摘要；应用前再次校验源 HEAD、状态摘要和补丁内容。应用后恢复使用同一份候选补丁的逆操作，并检查状态指纹，因此不会覆盖用户在应用后新增的修改。它不是文件系统级事务，也不会处理二次编辑后的冲突；发现冲突时保守停止，交给人工基于补丁处理。

## Git 共享仓库准备

`multi_model_codex` 原本不是 Git 仓库，因此本次没有擅自初始化、提交或推送。可以在本地直接执行 `git init`、提交并添加 remote；但 `git push` 的目标必须已经存在且当前账号有写权限。GitHub/GitLab 等服务通常需要先创建一个空远程仓库，或者使用已认证的官方 CLI 创建后再推送。不要把 API key、`.env`、`runs/`、`.venv/` 和运行工件提交到仓库。

本目录新增了 `CONTRIBUTING.md`、`SECURITY.md`、`CHANGELOG.md`、`REPOSITORY_SETUP.md` 和 pull request 模板。许可证没有代替用户选择法律授权；公开共享前应根据实际授权补充 LICENSE。
